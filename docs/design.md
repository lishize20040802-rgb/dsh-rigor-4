# Rigor 4 0.1.3 设计

Rigor 将任务读法、计划、执行事实、证据和独立审阅关联起来。原生 DSH 负责模型、会话、工具执行、子代理和 WebUI；插件通过工具注册、提示词 section 和生命周期事件补充约束。

## 模块边界

| 模块 | 职责 |
|---|---|
| index.js | 接原生服务、登记执行事实、门禁、子任务绑定、状态提交 |
| registration.js | 将本包的简单参数定义转为标准 JSON Schema，校验实际调用参数 |
| model.js | 纯状态变换、版本关系、证据和完成条件；不访问磁盘和模型 |
| store.js | 数据结构恢复、逐会话文件、独占锁、版本冲突检查 |
| tools.js | 六个工具的业务编排和错误出口 |
| payload.js | 解析并校验审阅者最终 JSON，拒绝损坏的新结论回退成旧批准 |
| children.js | 从原生事件日志提取子会话的最终消息与结束状态 |
| briefs.js | 按角色生成具体简报 |
| classify.js | 将已知工具名、参数与命令映射为读、写、子任务等类别 |
| prompt.js | 向模型说明操作流程和判断原则 |
| scripts/install.mjs | 通过官方 DSH/pnpm 安装包和预设、核对相对依赖与原生结果；不承诺事务回滚 |

## 执行事实

pre-execute 可以拒绝没有读法的文件修改；被拒绝的调用仍可能收到 post-execute。因此不能把看到一个 edit 的执行后事件当作文件修改成功。

插件分别记录成功修改、执行失败和拒绝尝试。到达 tools/execute 后失败，保守认为已知修改操作可能留下部分效果；原生 ABORTED_BEFORE_DISPATCH 明确排除该情况。非零退出码的命令仍保留真实命令及退出码，允许负向测试成为证据。tools/result 清理跳过执行后事件的异常路径，释放简报占用。

命令是否写入采用有限启发式分类，不能穷尽脚本内部行为。角色门禁也依赖已知工具名称；允许 shell 的审阅角色没有因此获得操作系统级只读保证。

## 版本和审阅

每份交付使用 { roundId, readingVersion, planVersion, workRevision } 标识。修改读法、计划或交付内容后，旧交付审阅和旧证据不能证明新版本。首次先做后读会保留迟到历史；重新核对需求可修订读法，但需要重新计划、取证和审阅。

后台子任务身份来自成功 spawn 返回的 subagentId。本次核对的官方前台 driver 返回 runId，插件还需从父代理注册表核实它是直接子会话。不能按注册表位置猜子任务身份，也不能手填不存在的 brief 凑出批准。审阅工具从该子会话自己的日志读取最终 JSON，并核实简报、角色、直接父子关系和交付版本。

准备角色使用不同有效期：clarify/diverge 对应本 round 的最新用户请求；plan-review 还对应计划版本；monitor 对应 round。它们可在适合的准备阶段完成，避免用交付版本检查把准备工作锁死。

artifact 证据记录真实绝对路径、文件类型、大小、修改时间和 SHA-256 指纹。相对路径以原生 agent 的工作目录解析。完成前重新读取指纹；重新链接已变化的产物会推进交付版本，使旧批准失效。指纹证明文件内容的一致性，无法证明内容符合需求；后者仍需要审阅。

## 请求边界

partial 和 blocked 保存未完成任务。下一条“继续”仍在相同 round，保留读法、计划和未关闭返工项。只有当前版本已报告 done，新用户请求才开启新 round，并保留有界历史摘要。真实子会话的角色在此过程中保留；普通用户引用 # Brief 不会让根会话变成只读子代理。

## 持久化

新状态位于 <DSH_HOME>/.rigor4/sessions/<sha256(sessionId)>.json，格式为 { format: 2, sessionId, revision, round }。每个会话独立文件，写入使用独占锁、revision 比较和临时文件重命名。

存储后端与安装入口均去除 DSH_HOME 首尾空白，空值回退到用户目录下的 .dsh，展开 ~、~/ 和 ~\，并在创建后端时按当前工作目录解析为绝对路径。这样后续工作目录变化不会把读写转移到另一套状态目录；本次只修正这一路径解析行为。

读取 revision 7 的调用只能以 7 为基线提交；若其他实例已经写到 8，旧提交返回冲突，不能覆盖新值。基线使用随状态对象传播的 Symbol token 记录，异步等待之后读取新数据也不会替旧对象换基线。JSON 不保存这个运行时 token。

旧 .rigor4/sessions.json 作为只读回退；新写入进入逐会话文件。旧记录中没有可验证快照的批准不会自动升级成当前有效批准。损坏状态不被空数据覆盖；持久化失败的工具返回 recorded: false。严重 IO/损坏错误会让该实例保持只读，修复原因后需重新加载实例。崩溃遗留 .lock 需先确认没有写入者再人工恢复，不能按固定超时强行抢锁。

## 安装与兼容性

运行时代码仅导入本包文件与 Node 内置模块。宿主服务由 ctx 注入，参数和输出使用宿主接受的标准 JSON Schema。安装包有自己的名称、状态目录和相对 profile 依赖，不导入旧代代码。

发布归档放在 <DSH_HOME>/third-party/archives，运行安装由原生 DSH/pnpm 管理到 profile 的 node_modules。`dsh-rigor-4 setup` / `uninstall` 默认执行，`--preview` 只读检查；底层安装脚本仍默认预览。入口调用 npm pack 和官方 dsh plugin，归一化自身的相对 file: 依赖，并自动沿用目标 profile 的 pnpm store。宿主通过 npm 的全局目录定位，也可显式指定，不从 npx 临时 peer 解析。锁文件继续由原生包管理器生成；该薄入口不承诺原生安装整体回滚。详见 installation.md。

当前契约核对基于 DSH 0.1.5-rc.2。原生源码显示 PTC 子调用经过同一工具流水线；自动测试与 SDK 验证不等同于完整真实模型任务验证。跨平台路径和 shell 预设已经分支，但其他操作系统仍需实际测试。

卸载使用 `node scripts/uninstall.mjs --dry-run` / `--apply`，行为和数据保留说明见 [中文 README](../README.zh.md#卸载)。
